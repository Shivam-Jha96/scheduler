Part I

Business Requirements Document (BRD)

1. Executive Summary & Vision Statement

BRD-01

WhatsApp serves over 2.7 billion users globally, yet provides no native capability to schedule personal or group messages. Users are forced to rely on battery-draining OS hacks, external calendar alarms, or manual reminders.

The WhatsApp Message Scheduler Bot closes this functionality gap by embedding a high-precision, conversational scheduling engine directly into WhatsApp chats. It achieves 100% peer-to-peer authenticity (messages sent from the user's real phone number), zero double-sends, and wall-clock invariance across all global timezones.

2. Business Problem & Market Opportunity

Current Market Frustrations
  • No native scheduled send button on WhatsApp iOS/Android personal apps.
  • External calendar alarms interrupt workflow and still require manual sending.
  • Official Meta Cloud API sends from business numbers, confusing contacts and violating P2P expectations.
  • Crude automation tools trigger Meta algorithmic SIM bans due to zero pacing.
The Business Opportunity
  • Prosumers & Freelancers: Schedule late-night drafts to deliver at 9:00 AM in client timezones.
  • Small Businesses: Automate appointment confirmations and billing reminders without expensive CRM seats.
  • Communities & Teams: Coordinate automated recurring standups and announcements in group chats.

5. Project Scope: In-Scope vs. Out-of-Scope

In-Scope (Phases 1–5)
  • 5-step guided wizard + fast-path CLI syntax (/schedule, /list, /cancel).
  • Personal account P2P companion node linking via 8-char pairing codes.
  • Official Cloud API Assistive CTA model with Utility Template fallback.
  • Two-tier hybrid scheduler (PostgreSQL 16 + BullMQ Redis buffer).
  • Wall-clock DST recurrence & 31st month-end anchor day preservation.
  • Multimodal support (Text, Image, PDF, Voice Notes, Video).
Out-of-Scope (Deferred / Prohibited)
  • Bulk unsolicited marketing broadcasts to unconsented phone numbers.
  • Automated scraping of public WhatsApp groups or address books.
  • Automated voice call scheduling or telephonic dialing.
  • In-app credit card or fiat currency payment processing gateway.

6. Core Business Rules (BR)

BR-01
Meta Messaging Compliance: Cloud API proactive messages beyond 24 hours must automatically route to pre-approved Meta Utility Templates to prevent API rejection.
BR-02
Zero Double-Send Guarantee: Under no network condition or worker crash may the system dispatch a duplicate message payload to the same recipient.
BR-03
Privacy & Cryptographic Vault: Signal protocol keys and Baileys session states must be encrypted at rest with AES-256-GCM. Personal data must be purged upon user request.
BR-04
Anti-Ban Rate Pacing: Personal Baileys sessions must simulate human typing pauses (35–55 ms/char) and enforce 8–15s jitter between distinct recipient messages.
BR-05
Wall-Clock Anchoring: Scheduled jobs are anchored to the user's localized IANA timezone, ensuring reminders never shift during seasonal DST clock changes.

Part II

Functional Requirements Document (FRD)

8. Functional Modules Overview

FRD-01

The functional specifications are partitioned into 7 discrete engineering modules:

FR-AUTH: Authentication & Linking

User auto-provisioning, 8-character pairing codes, Signal key AES-256-GCM envelope encryption, session reconnect state machine.

FR-WIZ: Conversational FSM Wizard

5-step interactive flow (Recipient vCard, Media/Text payload, Chrono temporal NLP, Recurrence rules, Confirmation preview).

FR-CLI: Fast-Path Command Grammar

Single-line command parser (/schedule, /list, /cancel, /edit, /timezone) with atomic BullMQ eviction.

FR-SCHED: Two-Tier Hybrid Scheduler

PostgreSQL 16 master ledger with partial indexing, 60s Look-Ahead Feeder, 5-minute BullMQ delayed queue buffer.

FR-REC: Recurrence & DST Invariance

Single active row pattern, Luxon calendar math, month-end anchor day preservation (Jan 31 → Feb 28 → Mar 31), reboot fast-forwarding.

FR-REL: Reliability & Zero-Double-Send

22-character deterministic WhatsApp stanza IDs, Redis Redlock mutex, dead-man's-switch sweeper, per-sender typing cadence pacing.

9. Module 1: Authentication & Device Linking (FR-AUTH)

Req ID Title Functional Specification
FR-AUTH-01 User Auto-Provisioning On first message, creates user record in users with default UTC timezone, locale en-US, status ACTIVE.
FR-AUTH-02 8-Char Pairing Code Flow On /link, requests pairing code via Baileys (sock.requestPairingCode) and displays 8-digit code for 1-tap mobile pairing.
FR-AUTH-03 AES-256-GCM Signal Key Vault Credentials and Signal pre-keys are encrypted before DB write with 256-bit KMS key and 12-byte IV (zero plain keys stored).
FR-AUTH-04 Session Lifecycle & Circuit Breaker Code 401 purges session; code 403 halts all socket operations immediately; code 515 cleanly reconnects after 5s backoff.

10. Module 2: Conversational Wizard State Machine (FR-WIZ)

Req ID Step / Feature Detailed Specification
FR-WIZ-01 Step 1: Recipient Resolution Extracts phone from vCard 3.0, E.164 text, or saved alias. Runs pre-flight verification on @g.us group chat permissions.
FR-WIZ-02 Step 2: Payload Capture Buffers text (up to 4,096 chars) or streams media to S3. Pre-warms attachments during T-5m look-ahead window.
FR-WIZ-03 Step 3: Temporal NLP Parses natural language (e.g. "tomorrow 9am") with chrono-node relative to user timezone. Rejects times ≤ now + 60s.
FR-WIZ-04 Step 4: Recurrence Rule Presents 5 options: Once, Daily, Weekdays, Weekly, Monthly. Sets anchor_day_of_month for monthly jobs.
FR-WIZ-05 Step 5: Confirmation Preview Renders card with [Confirm] (ACID commit), [Edit] (jumps to target step), and [Cancel] (purges draft).

11. Module 3: Fast-Path Command Grammar (FR-CLI)

FR-CLI-01: /schedule <target> <time> | <message> → Instant one-off schedule.
FR-CLI-02: /schedule --repeat <rule> <target> <time> | <msg> → Recurring schedule with DST invariance.
FR-CLI-03: /list [status] [page] → Paginated list with status badges (🟡 PENDING, 🟢 SENT, 🔴 FAILED).
FR-CLI-04: /cancel <job_uid> → Sets status to CANCELLED & invokes bullQueue.remove(idempotencyKey).
FR-CLI-05: /edit <job_uid> <time|message> <new_val> → Updates DB and resets in-flight timers.

12. Module 4: Two-Tier Hybrid Scheduling Engine (FR-SCHED)

Tier 1: PostgreSQL 16 Master Ledger

All scheduled jobs reside durably in PostgreSQL with monthly partitioning. A partial index on WHERE status IN ('PENDING', 'QUEUED') guarantees poller scan time < 0.2 ms.

Tier 2: 60s Look-Ahead Feeder & BullMQ

Feeder claims jobs maturing in the next 5 minutes using SKIP LOCKED and stages them into BullMQ delayed queue (memory footprint < 250 KB).

13. Module 5: Recurrence & Temporal Mathematics (FR-REC)

Wall-Clock DST Invariance:

Converts UTC to user IANA timezone, adds calendar interval, and converts back to UTC. Guarantees 9:00 AM stays 9:00 AM across 23h spring-forward and 25h fall-back clock shifts.

Month-End Anchor Day Preservation:

For jobs set on day 31: executes Feb 28/29 in February, then cleanly restores day 31 in March, April 30, and May 31 without perpetual day drift.

Reboot Fast-Forwarding:

After multi-hour server downtime, overdue recurring jobs step forward past NOW() to prevent bursts of historical spam messages upon recovery.
