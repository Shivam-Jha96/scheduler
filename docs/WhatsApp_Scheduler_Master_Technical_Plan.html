Executive Summary

The In-WhatsApp Message Scheduler Chatbot allows users (Alice) to message a bot conversationally within WhatsApp to schedule text, media, or recurring reminders for future delivery to personal contacts or group chats (Bob).

1. The Sender Identity Paradox

Meta's official Cloud API dispatches from a corporate business phone number (WABA), violating peer-to-peer expectations and triggering the 24-hour service window block (Error 131047).

2. Companion P2P Automation

WebSocket engines (@whiskeysockets/baileys) deliver authentic P2P messages from Alice's phone number, utilizing an 8-character pairing code, presence simulation, and AES-256-GCM Signal key encryption.

3. Two-Tier Hybrid Scheduler

Durable PostgreSQL 16 persistence paired with a 60s Look-Ahead Feeder and a 5-minute BullMQ delayed queue achieves sub-second accuracy with <250 KB Redis memory footprint.

Engineering Scrutiny Report

V2.0 Architectural Audit: 10 Critical Gaps Identified & Rectified

10 / 10 Resolved in V2 Spec
1. Baileys Deterministic Message ID Collision Protocol Bug

Flaw: 64-char SHA-256 hex was passed directly as stanza ID; WhatsApp servers silently drop IDs exceeding 22 hex characters.

Fix: Derived WA_MSG_ID = "3EB0" + SHA256(job_uid + ":" + next_run_iso).slice(0, 18).toUpperCase() (22 chars).

2. Sweeper Premature Re-Queue Race Condition Concurrency Bug

Flaw: Sweeper falsely reset `QUEUED` jobs staged 5 minutes ahead by checking updated_at.

Fix: Sweeper predicates on next_run_at_utc < NOW() - INTERVAL '3 minutes' for `QUEUED` records.

3. User Edit / Cancel Race During 5-Min Buffer Data Integrity

Flaw: Canceling or editing a job in DB failed to evict in-flight BullMQ delayed timers.

Fix: Synchronous BullMQ queue.getJob(idempotencyKey)?.remove() on `/cancel` or `/edit` + pre-flight DB checks.

4. Baileys Pairing Code Flow (Single-Phone UX) UX Blocker

Flaw: Users chatting with the bot on mobile cannot scan a QR code rendered on that same mobile screen.

Fix: Primary onboarding uses WhatsApp 8-Character Pairing Codes (sock.requestPairingCode(userPhone)).

5. Per-User Head-of-Line Blocking in Anti-Ban Throughput Bug

Flaw: Multiple workers sending concurrently from Alice's account triggered simultaneous overlapping typing indicators.

Fix: Per-Sender Redis Token Lock (pacing:sender:) enforcing sequential typing & 8–15s jitter.

6. Assistive Model 24h Self-Lockout Paradox Policy Bug

Flaw: If Alice schedules >24h ahead, her own 24-hour service window with the bot expires before the reminder fires.

Fix: Pre-approved Meta Utility Template (scheduled_reminder_cta_v1) fallback when now - last_inbound > 24h.

7. Envelope Encryption for E2EE Signal Keys Security Vulnerability

Flaw: Raw Baileys session credentials and Signal pre-keys stored in plain BYTEA columns.

Fix: Application-layer AES-256-GCM envelope encryption with KMS master keys and random 12-byte IVs.

8. DST Spring-Forward & Fall-Back Ambiguity Temporal Edge Case

Flaw: Undefined behavior when a 2:30 AM reminder hits a spring-forward gap or fall-back fold.

Fix: Deterministic Luxon disambiguation: advance past non-existent spring gaps; pin to earlier offset on folds.

9. Group Chat Membership Pre-Flight Check Delivery Failure

Flaw: Attempting to dispatch to group chats where Alice was removed or where "Only Admins Can Post" is active.

Fix: Pre-flight groupMetadata(jid) verification at T-60s staging; auto-transitions to FAILED and alerts Alice.

10. Media Payload Lifecycle & Pre-Warming Storage & Latency

Flaw: Uploading large video attachments to WhatsApp at the exact firing second caused 10–30s delivery delays.

Fix: Pre-warm/upload media during T-5m staging + automated S3 lifecycle cleanup 24h after final delivery.

6. HLD Subsystem Responsibilities & Boundary Contracts

Ingress Gateway

Terminates WebSocket sessions with WhatsApp's multi-device servers or verifies HMAC-SHA256 signatures on Cloud API webhooks. Decouples wire protocol from core scheduling logic.

Conversational FSM

Maintains 5-step interactive wizard state in Redis (15m sliding TTL). Validates inputs, parses temporal expressions via chrono-node, and normalizes phone numbers to E.164.

Two-Tier Hybrid Scheduler

Pairs durable PostgreSQL storage with a 60-second Look-Ahead Feeder and a 5-minute BullMQ sliding buffer. Guarantees zero memory exhaustion and sub-second dispatch precision.

Low-Level Design (LLD)

8. LLD Software Design Patterns & Class Architecture

Design Patterns
1. State Pattern (Conversational FSM)

Isolates step-by-step wizard logic into discrete state objects (IDLE, STEP1_RECIPIENT, STEP2_PAYLOAD, STEP3_TIMING, STEP4_RECURRENCE, STEP5_CONFIRM, EDIT_ROUTER). Each state implements input parsing, validation guards, and reprompting.

2. Strategy Pattern (Recurrence Engine)

Encapsulates wall-clock calendar mathematics behind interchangeable strategy classes: OnceStrategy, DailyStrategy, WeekdaysStrategy, WeeklyStrategy, MonthlyStrategy (with anchor day preservation), and CronStrategy.

3. Factory Pattern (Transport Engine)

WhatsAppTransportFactory produces either BaileysSocketTransport (for P2P Noise multi-device connections) or CloudApiWebhookTransport (for official Meta WABA accounts) based on user profile settings.

4. Producer-Consumer Priority Queue

The 60s Look-Ahead Feeder operates as a producer populating a Redis priority sorted set (BullMQ delayed queue), while distributed Delivery Workers act as consumers triggering execution with millisecond accuracy.

11. LLD Concrete Algorithmic Formulations

Algorithm 1: Multi-Modal Typing Cadence

Emulates human typing cadence before socket dispatch to evade Meta behavioral anti-bot heuristics:

// Mode 1: <= 120 characters
T_type = min(5.0, len * 0.045 + Gaussian(1.5, 0.4));
// Mode 2: > 120 characters (Review Delay)
T_type = Uniform(1.2, 2.8) seconds;
// Sequence: available -> composing (wait) -> paused -> send
Algorithm 2: Wall-Clock DST Invariance

Calculates recurrence in calendar dimension while preserving month-end anchor days:

t_local = Luxon.fromJSDate(last_utc, { zone: user_tz });
next_local = t_local.plus({ days: 1 }); // 23h/25h safe
target_day = min(anchor_day, next_local.daysInMonth);
next_local = next_local.set({ day: target_day });
return next_local.toUTC().toJSDate();

12. LLD Two-Tier Hybrid Scheduling Engine

Pure Redis Delay Queue

1M jobs scheduled months ahead consumes ~1.8 GB RAM. Risk of data loss on non-AOF restart.

Pure DB Polling

20 workers polling every 1s generate 1.72M queries/day, choking CPU and connection pools.

Two-Tier Hybrid Engine

PostgreSQL holds all future jobs (0 MB RAM). 60s Feeder stages next 5m into BullMQ (<250 KB RAM).

16. Zero-Double-Send Guarantee & Rectified Recovery Sweeper

Four distinct layers protect against duplicate message transmissions:

1. BullMQ Job ID

Staged using opts: { jobId: idempotencyKey }. Redis deduplicates overlapping feeder ticks.

2. Redis Mutex

Worker acquires SET lock:job: NX EX 60 and checks GET done:job: before socket write.

3. Pre-Flight DB State

Atomically updates status='PROCESSING' WHERE status='QUEUED'. Zero rows match if user cancelled.

4. 22-Char Stanza ID

Passed as WA_MSG_ID = 3EB0... into Baileys. WhatsApp network automatically deduplicates retransmissions.

17. Anti-Ban Safeguards & Envelope Encryption

Per-Sender Outbound Serialization

Workers acquire pacing:sender: to serialize dispatches from Alice's account, preventing unnatural concurrent typing states across multiple chats.

AES-256-GCM Signal Key Vault

Baileys session credentials and Signal identity/signed pre-keys are encrypted before DB storage using a 256-bit KMS Master Key and per-row 12-byte IVs.
